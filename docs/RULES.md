### PKL100 dangerous-import

**critical** - Pickle imports a callable on the deny-list.

Unpickling resolves GLOBAL/STACK_GLOBAL/INST through find_class, which imports the module and fetches the attribute. Deny-listed names (process execution, code evaluation, import machinery, file/network access, nested deserializers, attribute-access gadgets) give an attacker code execution or an equivalent primitive.

### PKL101 unknown-import

**medium** - Pickle imports a name that is not on the allow-list.

Importing a module runs its top-level code, and the imported object may be invoked later through REDUCE/BUILD. Names outside the allow-list need review.

### PKL102 unknown-callable-invoked

**high** - Pickle invokes a callable that is not on the allow-list.

REDUCE, NEWOBJ, NEWOBJ_EX, OBJ and INST call the object they reference. Calling an unreviewed callable with attacker-chosen arguments is the core pickle exploit.

### PKL103 dynamic-import

**high** - STACK_GLOBAL operands are not compile-time string constants.

When the module or attribute name is computed at runtime the scanner cannot tell what is imported; benign serializers always emit literal strings.

### PKL104 attribute-traversal

**high** - Imported name walks through a dunder attribute chain.

Protocol 4 find_class resolves dotted names attribute by attribute, so a name such as 'Foo.__init__.__globals__' reaches arbitrary objects from an allowed module.

### PKL105 extension-registry

**high** - Pickle uses EXT1/EXT2/EXT4 extension-registry opcodes.

Extension codes are resolved through copyreg's process-global registry, so the imported callable cannot be determined statically.

### PKL106 indirect-call

**high** - A runtime-computed value is called.

REDUCE on the result of another call (for example getattr(...)(...)) invokes a callable chosen at load time. Benign pickles call imported names directly.

### PKL107 global-mutation

**high** - BUILD/SETITEM/APPEND targets an imported module-level object.

Applying state to a class or module object rather than to a fresh instance mutates interpreter-global state, a known pickle persistence and hijack trick.

### PKL108 persistent-load

**medium** - Pickle uses PERSID/BINPERSID outside a recognised container.

Persistent IDs are resolved by the loader's persistent_load hook; the behaviour depends entirely on application code the scanner cannot see.

### PKL109 nested-pickle

**medium** - A bytes constant inside the pickle is itself a pickle.

Embedded pickles are usually unpacked by a later loads() call; the inner stream is scanned recursively and its findings are reported with a nested location.

### PKL110 multiple-pickles

**medium** - The stream contains more pickles after the first STOP.

Loaders that call load() repeatedly execute every pickle in the stream, while naive scanners stop at the first STOP opcode.

### PKL111 trailing-data

**low** - Unparsed bytes follow the final STOP opcode.

Trailing data is ignored by pickle.loads but may hide a second payload or indicate a polyglot file.

### PKL112 malformed-pickle

**medium** - The pickle stream is truncated or structurally invalid.

Malformed streams cause differences between scanners and loaders; the part before the error is still analysed.

### PKL113 unknown-opcode

**high** - An opcode byte that no pickle protocol defines was found.

The stream cannot be analysed past this point.

### PKL114 unsupported-protocol

**high** - PROTO announces a protocol newer than 5.

No released Python understands it; the file was crafted or corrupted.

### PKL115 malformed-global-name

**high** - GLOBAL/INST/STACK_GLOBAL names are not valid dotted identifiers.

Odd characters, empty segments or relative imports in a global name indicate tampering or an attempt to confuse name-based filters.

### PKL116 resource-limit

**medium** - Analysis stopped at a configured resource limit.

Opcode, stack, memo or nesting limits protect the scanner from hostile inputs; the stream may contain more content than was analysed.

### ZIP200 path-traversal

**high** - Archive member name escapes the extraction directory.

Absolute names, drive letters or '..' segments let extraction write outside the target directory (zip-slip).

### ZIP201 duplicate-member

**medium** - Archive contains two members with the same name.

Different readers pick different copies, so a scanner and a loader can see different content. Every copy is scanned; findings in the k-th copy are located at `name#k`.

### ZIP202 decompression-bomb

**medium** - Member compression ratio or size exceeds limits.

Highly compressed members exhaust memory or disk when extracted.

### ZIP203 encrypted-member

**medium** - Archive member is encrypted.

Encrypted content cannot be inspected; ML archives are never encrypted.

### ZIP204 symlink-member

**high** - Archive member is a symbolic link.

Symlinks in extracted archives redirect later writes or reads outside the tree.

### ZIP205 malformed-archive

**medium** - The zip structure could not be read.

Damaged central directories are interpreted differently by different readers.

### ZIP206 torchscript-code

**medium** - PyTorch archive contains TorchScript source code.

torch.jit.load compiles and runs the code/ directory; it is a program, not data.

### ZIP207 missing-storage

**medium** - A persistent storage reference has no matching archive record.

PyTorch resolves storages by key; dangling or path-like keys are inconsistent with torch.save output.

### ZIP208 embedded-executable

**medium** - Archive embeds source code or native binaries.

Python sources, shared libraries and scripts inside model archives are a common way to smuggle code next to weights.

### ST300 header-size-invalid

**medium** - Header length prefix is zero, too large or beyond the file.

The 8-byte little-endian prefix must describe a header that fits in the file and stays under the 100 MB limit used by the reference implementation.

### ST301 header-not-json

**medium** - Header is not a UTF-8 JSON object.

Only a JSON object is valid; parsers disagree on anything else.

### ST302 invalid-dtype

**medium** - Tensor dtype is not a safetensors dtype.

Unknown dtypes are rejected by the reference loader.

### ST303 invalid-shape

**medium** - Tensor shape is not a list of non-negative integers.

Malformed shapes break size computations in loaders.

### ST304 offset-size-mismatch

**medium** - Tensor byte range does not match dtype size times element count.

Mismatched ranges let a reader access memory outside the intended tensor.

### ST305 overlap-or-gap

**medium** - Tensor byte ranges overlap or leave holes.

The format requires tensors to tile the data buffer exactly; overlaps alias data and holes can hide content.

### ST306 duplicate-key

**medium** - Header JSON contains duplicate keys.

JSON parsers keep either the first or the last duplicate, a classic parser differential.

### ST307 bad-metadata

**low** - __metadata__ is not a string-to-string map.

The specification restricts metadata to string values.

### ST308 data-length-mismatch

**medium** - Data section length does not match the tensor table.

Truncated files or appended payloads (polyglots) change the byte buffer size.

### GG400 malformed-header

**medium** - GGUF header or key/value section is truncated or invalid.

Readers that trust truncated headers read out of bounds.

### GG401 unsupported-version

**medium** - GGUF version is not 1, 2 or 3.

Unknown versions change field widths.

### GG402 implausible-count

**high** - Tensor or metadata count cannot fit in the file.

Huge counts drive allocations sized from attacker input (llama.cpp has had several heap overflows of this shape).

### GG403 string-out-of-bounds

**high** - A length-prefixed string or array extends beyond the file.

Length fields are the primary out-of-bounds read vector in GGUF parsers.

### GG404 invalid-value-type

**medium** - Metadata value type id is unknown.

Unknown types make the remainder of the header unparseable.

### GG405 duplicate-key

**medium** - Metadata key appears more than once.

Readers disagree on which value wins.

### GG406 invalid-tensor-dims

**high** - Tensor dimension count or sizes are invalid or overflow.

ggml supports at most 4 dimensions; overflowing element counts corrupt size arithmetic.

### GG407 unknown-tensor-type

**medium** - Tensor uses an unknown ggml type id.

The data size cannot be validated.

### GG408 tensor-out-of-bounds

**high** - Tensor data extends beyond the end of the file.

Readers that map tensors by offset would read past the buffer.

### GG409 misaligned-tensor

**medium** - Tensor offset or general.alignment is invalid.

Offsets must be multiples of a power-of-two alignment.

### GG410 tensor-overlap

**medium** - Two tensors share bytes.

Overlapping tensors alias each other's data.

### GG411 chat-template-injection

**high** - Chat template contains Jinja constructs that reach Python internals.

Templates are rendered by Jinja; dunder access such as __class__ or __globals__ is the server-side template injection pattern behind CVE-2024-34359.

### GG412 duplicate-tensor-name

**medium** - Two tensors share a name.

Loaders resolve tensors by name.

### GG413 oversized-array

**medium** - Metadata array or nesting exceeds limits.

Large arrays and deep nesting are resource-exhaustion vectors.

### GG414 invalid-utf8

**low** - A GGUF string is not valid UTF-8.

The specification requires UTF-8 strings.

### GG415 block-size-mismatch

**medium** - Tensor row length is not a multiple of the quantisation block size.

Quantised types store whole blocks; a partial block means the size arithmetic is inconsistent.

### OX500 malformed-protobuf

**medium** - ONNX protobuf could not be decoded.

A damaged model is parsed differently by different runtimes.

### OX501 external-data-absolute-path

**high** - External tensor data uses an absolute path.

Absolute locations make the runtime read arbitrary files on the host.

### OX502 external-data-path-traversal

**high** - External tensor data path escapes the model directory.

'..' segments or symlinks let a model read files outside its directory (CVE-2022-25882 class).

### OX503 external-data-missing

**medium** - External data file does not exist next to the model.

The model is incomplete or expects files placed by another channel.

### OX504 external-data-range-invalid

**medium** - External data offset/length is invalid or beyond the file.

Out-of-range offsets cause out-of-bounds reads in runtimes.

### OX505 custom-op-domain

**low** - Graph uses operators from a non-standard domain.

Custom operators require native libraries registered at load time.

### OX506 nesting-too-deep

**medium** - Graph or message nesting exceeds the configured depth.

Deep nesting is a stack-exhaustion vector for recursive protobuf parsers.

### KR600 lambda-layer

**high** - Keras model contains a Lambda layer.

Lambda layers carry Python bytecode (marshal) that runs when the model is loaded with safe_mode=False or by Keras 2.

### KR601 dangerous-reference

**critical** - Keras config references a deny-listed callable or class.

Keras deserialises {'module', 'class_name'} references by importing them; deny-listed targets are code execution (CVE-2025-1550 class).

### KR602 unknown-function-reference

**high** - Keras config references a function outside the allow-list.

Function references are imported and called during deserialisation.

### KR603 custom-object

**medium** - Keras config instantiates a class from outside the Keras namespaces.

Custom objects require user code at load time and are a supply-chain surface.

### KR604 malformed-config

**medium** - Keras archive config is missing or is not valid JSON.

The model cannot be validated.

### NP700 object-array

**medium** - NumPy array uses object dtype, stored as a pickle.

Loading needs allow_pickle=True; the embedded pickle is scanned recursively.

### NP701 malformed-npy

**medium** - NumPy .npy header is invalid.

The header must be a Python literal dict with descr/fortran_order/shape.

### GEN900 format-mismatch

**medium** - File extension does not match the detected content.

Loaders choose a deserializer by extension; a pickle named .safetensors defeats format-based trust decisions.

### GEN901 scan-error

**medium** - The file could not be fully scanned.

I/O failures or parser limits prevented a complete analysis.

### GEN903 polyglot

**high** - File is simultaneously valid as two different formats.

A file that is both a pickle and a zip archive (or a safetensors file with a zip trailer) is loaded differently depending on which reader opens it.

### GEN902 file-too-large

**low** - File exceeds the configured size limit and was not scanned.

Raise --max-file-size to scan it.
